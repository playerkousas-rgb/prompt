# 組合章怎麼切 · 巾圈有幾種

這份是回答兩個問題的功課：
1. 做章最難的是外框，更難的是組合章 —— 是不是「先定外框，再像拼圖那樣切開」？
2. 巾圈種類很多，要先搞清楚種類才知道 JSON 怎麼出。

---

## 一、外框：為什麼它最難，怎麼把它變簡單

外框難，是因為使用者腦裡想的形狀、工廠能做的形狀、生圖 AI 畫得出來的形狀，是三回事。
所以 `lib/badge/shapes.ts` 把「形狀」變成同時輸出三樣東西的一筆資料：

| 欄位 | 用途 |
| --- | --- |
| `path(box)` | 真正的 SVG 路徑 → 中欄對照圖就照這個形狀畫，所見即所得 |
| `keywords` | 一句精準英文 → 餵給生圖 AI |
| `merrowable` | 能不能包邊 → 不能的話立刻在圖下方警告，並寫進規格單 |

目前 11 種：圓、橢圓、圓角方、長方/旅條、盾形、六角、菱形、口袋蓋形（OA flap）、
綬帶燕尾旗、花邊圓（扇貝邊）、異形（跟著圖走）。

**規則（來自工廠資料）**：包邊（Merrow）固定 3–4 mm，而且只能走沒有凹角的規則外形；
其餘一律雷切／熱切，邊可以細到 1 mm，但異形不能有細長突出，洗幾次就會翹。

## 二、組合章：答案是「先定外框再切」，但有三個關鍵修正

### 2.1 對的部分
先畫整張母圖、再切開，是唯一正確的順序。先各畫各的再湊，永遠湊不準 ——
顏色、線寬、地平線高度都會對不上。

### 2.2 修正一：切開 ≠ 把圖剪開，因為每片都會「長出自己的邊」
這是組合章最常翻車的地方。四片切開之後，每一片都要各自收邊：

- 包邊：每片 3.5 mm → 兩片之間 **7 mm** 的縫
- 雷切：每片約 1 mm → 兩片之間 **2 mm** 的縫

也就是說，橫跨切線的那條地平線一定會被切斷。解法不是避免，而是**把切縫當設計元素**：
全套用同一個邊色，當拼圖的「填縫」；臉、字、關鍵圖形一律避開切線。
（工具裡就是「切縫（共用邊色）」那一格，而且預設會寫進母圖提示詞的 `cut_lines`。）

### 2.3 修正二：每一片都必須單獨看得懂
交換章九成的時間是單獨躺在別人的章板上，拼完整的樣子一輩子只出現在合照裡。
所以「每片的主角」是獨立欄位，而不是從母圖自動切；
`composition_rule` 也明寫 *make every single piece readable on its own*。

### 2.4 修正三：生圖一定要分兩段
沒有任何生圖模型能一次吐出 N 張能對齊的圖。所以輸出長這樣：

- **主提示詞** = 母圖（`stage: STEP 1 of 2`），一次生出拼好的整張
- **附件一「逐片提示詞」** = 第二階段，把母圖當參考圖，一次生一片，
  每段都寫好 `crop:`（這片是母圖的哪一塊）與「補上自己的邊」
- **附件二「規格單（組合章版）」** = 給工廠：拼合尺寸、共用邊色、拼合公差、
  以及最容易被忽略的那一條 —— **N 片 = N 次打樣費 + N 份 MOQ**

### 2.5 五種切法（按「做得出來的難度」排）

| 切法 | 片數 | 每片還是規則形？ | 要注意 |
| --- | --- | --- | --- |
| 中心章 + 外圈衛星 | 3–6 | ✅ | 風險最低，不需對齊，每片都能單獨交換。收藏套組最常見 |
| 橫切條 | 2–4 | ✅ | 風景、山稜、地平線構圖最適合 |
| 棋盤格 2×2 / 3×2 | 4, 6 | ✅ | 唯一還能包邊的「真的拼得起來」切法 |
| 切片（切蛋糕） | 2,3,4,6 | ❌ | 尖端最細處要留 ≥ 4 mm，必須雷切 |
| 系列式（同框換角色） | 2–6 | ✅ | 不切開：共用同一個框與版型，每片只換主角。生產最單純 |
| 真·拼圖咬合 | 2–4 | ❌ | 榫頭 ≥ 8 mm，只建議 PVC 或織章；電繡榫頭會散。成本最高 |

咬合拼圖另外有三格細節：**榫頭形狀**（圓榫最好脫模／燕尾榫咬最牢／方榫最俐落）、
**榫頭寬度**（8–15 mm）、**配合鬆緊**（緊配 ±0.3 mm 拿得起來／標準 ±0.8／鬆配 ±1.5），
三格都會同時寫進生圖提示詞的 `set.interlock` 與規格單的公差提醒。

對照圖右上角有「看拆開 / 看拼起來」：拆開模式會把每一片各自的輪廓往外推開畫出來，
直接看得到每片單獨長什麼樣。

## 三、巾圈有幾種：先分構造，不要先分材質

查過 Gilwell／BSA slide-of-the-month 傳統、台港團本部做法、工廠目錄與 Etsy 實售品之後，
結論是**材質是次要的，構造才是主要的**。構造決定了四件事：
有沒有可以放圖的正面、要不要問編法、字能刻多小、生圖該用什麼角度拍。

構造只有五種（`lib/badge/woggleTypes.ts` 的 `family`）：

| family | 中文 | 有正面嗎 | 領巾怎麼過 |
| --- | --- | --- | --- |
| `knot` | 繩結環 | ❌ 沒有正面，設計＝編法＋配色 | 穿過編織環的中心 |
| `solid` | 實心環 | ✅ 環身就是面 | 穿過環的內孔 |
| `plate` | 平片滑扣 | ✅ 一張小海報 | 穿過片上的孔，或背後焊／黏的環 |
| `figurine` | 立體造型 | ✅ 整隻就是圖 | 穿過背後黏的短管 |
| `fabric` | 布面環 | ✅ 繡面 | 穿過縫成筒的布 |

**AI 最常畫錯的就是這裡** —— 平片類會被畫成一個圈。所以 JSON 固定有一條
`form.how_it_holds`，用白話寫清楚領巾到底怎麼穿過去。

### 12 個實際款式

| 款式 | family | 最小字高 | 一句話 |
| --- | --- | --- | --- |
| ~~皮繩土耳其頭結~~ | knot | — | 極偉原型，木章領袖款（手工，**不列入選項**） |
| ~~傘繩編結 550~~ | knot | — | 最便宜好做，雙色螺旋（手工，**不列入選項**） |
| ~~打包帶編織~~ | knot | — | 台灣團環保做法（手工，**不列入選項**） |
| 皮片滑扣（二孔/三孔/壓扣） | plate | 3 mm | 最好客製，可壓印名字 |
| 木 / 竹 | solid | 2 mm | 雷雕是燒焦褐色，不是彩色 |
| 3D 列印 | solid | 2.5 mm | 內徑 22 mm 是社群標準；單色只有凹凸兩種層次 |
| 金屬壓鑄 + 琺瑯 | plate | 1 mm | 質感最好，要開模；顏色必須被金屬線圍住 |
| PVC 軟膠 | solid | 1.5 mm | 防水摔不壞，量大最便宜 |
| 繡章 / 織帶捲筒 | fabric | 4 mm | 跟整套章風格最一致，裡面要襯塑膠環 |
| 立體造型公仔 | figurine | 3 mm | BSA「每月一款」傳統，重點是剪影 |
| 樹脂包埋 | solid | 3 mm | 營火灰、沙、乾燥花封進去 |
| 串珠 / 編繩包管 | fabric | 6 mm | 珠子＝像素，曲線與小字一律放棄 |

### JSON 怎麼跟著變

欄位會依構造自動出現／消失（`FieldDef.showIf`）：

- `knot` → 出現「編法」「繩子配色走法」；**不出現**正面圖案、童軍符號、刻字
- `plate` / `figurine` → 出現「領巾怎麼穿過」
- 有正面的才出現圖案與刻字，且 `lettering_rules` 會帶入該做法的最小字高

輸出結構：

```
{ subject, use,
  form: { family, construction, [weave], [cord_pattern], [mounting], how_it_holds, dimensions },
  face: {...}            // 沒有正面的構造，這裡改成一句 "no decorated face"
  style: { art_direction, material_colour, surface, making_note, constraint },
  render, negative_prompt }
```

### 繩結類為什麼不列入選項

使用者的目的是**出設計圖交工廠生產**，繩結類是手工編的、沒有開模也沒有規格可談，
所以 UI 只列 9 款可量產的（資料仍保留在 `woggleTypes.ts` 的 `handmade: true`，
哪天要做手作教學再打開就好）。

同樣因為目的是交工廠，巾圈也和紀念章一樣**多出一份中文規格單**：
構造、材質、尺寸寫法（平片給正面 W×H、環狀給內徑×高）、色數、刻字、表面處理、
領巾固定方式、開模／製版方式、數量，外加「開模前先寄一條實際領巾試穿」這種實務提醒，
以及報價要回覆的 5 項（開模費與模具保管、單價級距、打樣、Pantone 公差、交期與包裝）。

`making_note` 是每一種做法自己的坑（例如打包帶一定要寫 flat bands，
不然 AI 會畫成圓繩；樹脂包埋要寫 suspended inside，不然會變成印在表面）。

## 四、讓生圖 AI 真的看懂這份 JSON（`lib/badge/promptRules.ts`）

首要目的是 JSON，不是規格單。實測模型最常犯三個錯，所以每一份章 / 組合章 / 巾圈的
JSON 最前面都固定掛一組 `how_to_read`：

1. **把中文描述當成要印的字** → 明寫「中文值是要畫的內容，不是要印的字；
   唯一可以出現在圖上的文字，是這幾個鍵的值」，並且逐一列出那些鍵（空的不列）。
2. **把設計稿畫成有人戴著的照片** → 明寫 no person / no hands / no uniform /
   no packaging / no mockup perspective（巾圈若有指定領巾顏色，才例外允許一條領巾當道具）。
3. **文字自由發揮** → `typography.rules` 要求逐字照抄、繁體不可被簡體或近形字取代。

另外所有「給 AI 看」的值一律英文：配色用英文色名（不是中文選項標籤）、
每種做法的坑用 `noteEn`（中文版只留在 UI 與規格單）。

## 五、章 + 巾圈成套

紀念章的工藝那一組多了一格「要不要順便出配套巾圈」。選了之後，章的主題、主視覺、
童軍符號、配色、色數、年份會自動搬進巾圈系統，借它的 `build()` 產出**第二份生圖 JSON**，
附在提示詞下面（風格會依材質自動對應：皮革 / 布面走傳統木章感，軟膠 / 金屬走現代極簡）。
兩件東西因此共用同一組英文色名與同一個主圖描述，擺在一起才像一套。
